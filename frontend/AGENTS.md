# 프런트엔드 작업 지침

이 문서는 `frontend/`와 하위 디렉터리에서 작업하는 에이전트와 개발자를 위한 규칙이다. 2026-09-26에 진행한 아토믹 구조 리팩토링과 사용자 지정 코드 포맷을 기준으로 한다. 사용자의 현재 요청을 우선하며, 구조나 규칙을 의도적으로 변경했다면 이 문서와 `README.md`도 함께 갱신한다.

## 1. 아토믹 디자인 적용 방법

아토믹 디자인은 **UI 구성 단위**에 적용한다. 데이터 조회와 비즈니스 로직까지 atoms/molecules/organisms에 억지로 넣지 않는다.

| 위치 | 책임 | 기존 예시 |
| --- | --- | --- |
| `src/components/atoms/` | 도메인 지식이 적은 기본 UI | `Button`, `Badge` |
| `src/components/molecules/` | 기본 UI를 조합한 작은 기능 | `ModeSwitch`, `StatCard`, `StepDirections`, `PlaceMapLink` |
| `src/components/organisms/` | 독립적인 화면 영역과 사용자 흐름 | `RouteSectionManager`, `RouteSettings`, `RouteTimeline`, `RouteOverview`, `PlaceForm` |
| `src/components/templates/` | 공통 화면 틀과 배치 | `PlannerLayout` |
| `src/pages/` | 훅과 UI 연결, 화면 간 동작 조율 | `PlannerPage` |
| `src/hooks/` | React 상태, API 호출과 비동기 수명 관리 | `usePlannerData`, `useRoutePlan` |
| `src/lib/` | 공통 타입, API 클라이언트, 순수 계산 함수 | `types.ts`, `api.ts`, `planner.ts`, `mapsUrl.ts` |

새 기능을 추가할 때는 다음 순서로 배치한다.

1. 기존 컴포넌트와 훅으로 해결할 수 있는지 먼저 확인한다.
2. React나 API 없이 계산할 수 있는 규칙은 `lib`의 순수 함수로 만든다.
3. API 요청·상태 동기화·요청 취소/무효화는 해당 책임의 훅에서 처리한다.
4. UI는 기능 단위로 조합하고, 필요한 값과 의미 있는 콜백을 props로 전달한다.
5. Page에는 화면 조립과 날짜·선택·모달 등 화면 간 조율을 남긴다.

작은 컴포넌트가 상위 Page를 import하지 않도록 한다. 파일 수를 늘리기 위해 단순 태그를 무조건 분리하지 않는다. 재사용성, 독립적인 책임, 테스트 가능성을 기준으로 분리한다.

## 2. 이번 리팩토링에서 정한 책임 경계

| 모듈 | 관리하는 내용 |
| --- | --- |
| `usePlannerData` | 장소·코스·구간 초기 조회, 장소 변경, 코스 배정, 변경 후 새로고침, 변경 작업의 오류·진행 상태 |
| `useRouteSections` | 날짜별 구간 선택, 추가·이름 변경·삭제 |
| `useRouteSettings` | 구간별 출발·도착지와 시간 설정, 출발·도착지 저장, 날짜 이동·삭제에 따른 설정 정리 |
| `useRoutePlan` | Valhalla 요청, 350ms 지연, 이전 요청 응답 무효화, 이용 불가 상태, 강제 재계산 |
| `lib/planner.ts` | 날짜 목록, 필수 STEP 배치, 장소 정렬, 경로 입력 비교, 날짜별 설정 이동·삭제 |
| `RouteSectionManager` | 구간 탭과 관리 폼의 표시·입력 상태 |
| `RouteSettings` | 시간대·출발 시각·출발/도착 장소 설정 UI |
| `RouteOverview` | 지도, 이동 통계, 일정 요약 |

Page의 로직을 통째로 거대한 `usePlanner` 하나로 옮기지 않는다. JSX 이벤트 핸들러 안에 긴 API 처리와 상태 변경을 다시 누적하지 않는다. 반복되는 장소 수정·삭제·날짜 변경 동작은 공통 핸들러를 사용한다.

컴포넌트 props는 필요한 값과 동작을 명시한다. 페이지 전체 상태나 여러 setter를 편의상 모두 넘기지 않는다. 기존 폼의 국소적인 입력 상태는 해당 폼에 둔다. 기존 컴포넌트에 남아 있는 API 호출은 관련 기능을 수정할 때 책임에 맞춰 점진적으로 정리하고, 무관한 기능까지 확대 변경하지 않는다.

줄 수 자체를 품질 목표로 삼지 않는다. JSX를 여러 줄로 펴면 파일은 길어질 수 있다. 책임 분리와 읽기 쉬운 흐름을 유지하는 것이 우선이다.

## 3. 반드시 보존할 동작

- 지도 표시는 Leaflet + OpenStreetMap, 경로 계산은 Valhalla를 사용한다. Google 지도 SDK나 Routes API를 다시 추가하지 않는다.
- Google 지도는 장소 링크와 STEP 사이 길찾기 링크로 연결한다. 장소 검색은 현재 Photon을 사용한다. 검색 제공자 변경은 별도 기능 요청으로 다룬다.
- Map 모드는 방문 순서와 위치만 표시하며 경로 API를 호출하지 않는다.
- 시간대·출발 시각을 바꾸어도 즉시 경로를 재계산하지 않는다. 재계산 버튼을 누르면 최신 설정을 사용한다. 이전 설정으로 계산한 결과에는 변경 안내를 유지한다.
- 메모·이름·체크리스트 변경만으로 경로를 재계산하지 않는다. 표시 중인 장소 정보는 최신 값으로 갱신한다.
- 날짜·구간·이동수단 전환 뒤 늦게 도착한 이전 요청 응답이 현재 결과를 덮어쓰지 않도록 한다.
- 필수 STEP 순서, 왕복의 동일한 출발/도착지, 다른 날짜 장소의 제외 규칙을 유지한다.
- 날짜 이동·삭제 시 해당 날짜의 모든 구간 설정을 함께 처리한다. 다른 날짜의 설정은 유지한다.
- 실패 시 닫히면 안 되는 폼에는 실패를 호출자에게 전달한다. `runMutation`은 오류를 다시 던지고, `mutate`는 페이지 오류 표시를 사용하는 동작에 쓴다.
- 대중교통 최적화 실패를 성공한 경로처럼 표시하지 않는다. 구간별 Google 길찾기 링크를 제공하는 현재 동작을 유지한다.

## 4. 코드 가독성과 포맷

기준 파일은 `.prettierrc.json`과 `scripts/format.mjs`이다.

- 들여쓰기는 스페이스 4칸을 사용한다.
- import, 구조 분해, 객체, JSX 속성의 중괄호 안쪽에 공백 1칸을 둔다: `{ value }`.
- 연산자 양옆에 공백을 두고, 여러 실행문을 한 줄에 붙이지 않는다.
- JSX의 자식 태그와 여닫는 태그를 각각 줄로 구분한다.
- JSX 자식의 동적 표현식은 `{`, 표현식, `}`를 별도 줄로 배치한다.
- 짧은 단일 속성 태그는 한 줄로 유지할 수 있다. 여러 속성은 속성별로 줄을 나누고 `>` 또는 `/>`는 별도 줄에 둔다.
- 기본 줄 너비는 100자, JavaScript/TypeScript 문자열은 작은따옴표를 사용한다. 긴 문자열을 의미가 바뀌도록 강제로 자르지 않는다.
- JSX에서 의미 있는 공백을 유지하는 `{ ' ' }`와 문자열 표현식은 짧게 한 줄로 유지할 수 있다. 포맷만을 이유로 화면 텍스트나 공백을 바꾸지 않는다.

```tsx
import { MapPin } from 'lucide-react';

const options = { enabled: true };

const content = (
    <div
        className="route-content"
        aria-busy={ busy }
    >
        <MapPin size={ 16 } />
        {
            visible && (
                <span>
                    {
                        title
                    }
                </span>
            )
        }
    </div>
);
```

`frontend/`에서 다음 명령을 사용한다.

```sh
npm run format
npm run format:check
```

포맷 명령은 `src`의 TypeScript·TSX·CSS 등을 대상으로 한다. 일반 Prettier만 실행하면 JSX 전용 줄바꿈 규칙이 유지되지 않으므로 프로젝트 명령을 사용한다. 이 스크립트는 포맷 전후의 변환된 JavaScript 구문과 JSX 텍스트를 비교하고, 차이가 감지된 파일은 저장하지 않는다. 이 검사는 타입 검사나 기능 테스트를 대체하지 않는다.

## 5. 변경 후 검증

`frontend/`에서 실행한다. Node.js 22.18 이상을 사용한다.

```sh
npm run format:check
node --test tests/*.test.mjs
npm run build:nginx
```

- `/yeodong/`에서 서비스하므로 최종 서비스용 빌드는 `build:nginx`를 사용한다. 일반 `build`는 루트 경로용이다.
- 순서·날짜·경로 입력 규칙을 변경하면 경계 조건을 검증하는 테스트를 보완한다. 단순 스타일 변경만을 위해 구현을 복제하는 테스트를 만들지 않는다.
- 화면이나 상태 흐름을 변경하면 관련 브라우저 동작을 확인한다: Map/도보 전환, 수동 재계산, 날짜·구간 전환, 지도·STEP 링크, 폼 열기/닫기.
- 실제 사용자 일정을 테스트 목적으로 삭제·이동하거나 임의 장소를 저장하지 않는다. 데이터 변경 검증에는 임시 데이터나 격리된 환경을 사용한다.
- 기존 사용자 수정과 IDE 설정을 덮어쓰지 않는다. 생성물·의존성 디렉터리를 직접 수정하지 않는다.
- 결과를 보고할 때 변경한 책임 경계와 실제 수행한 검증을 명시한다. 실행하지 않은 검증을 완료했다고 쓰지 않는다.

## 6. 사용한 스킬과 도구 기록

이번 아토믹 리팩토링 및 가독성 작업에서는 **별도의 `SKILL.md` 기반 스킬을 적용하지 않았다.** 아토믹 디자인은 설계 방법이며, 아래 개발 도구는 에이전트 스킬과 구분한다.

| 실제 사용한 도구/방법 | 용도 |
| --- | --- |
| 파일 읽기·수정 및 셸 실행 | 기존 책임 분석, 훅·컴포넌트 분리, 문서 작성 |
| Prettier | 기본 TypeScript·JSX·CSS 포맷 |
| TypeScript Compiler API | JSX 전용 줄바꿈·공백 처리와 변환 전후 구문 비교 |
| TypeScript / Vite | 타입 검사와 `/yeodong/` 빌드 |
| Node.js 내장 테스트 러너 | STEP 순서·날짜 처리·Google 링크 검증 |
| `mcp__cua_repl` 브라우저 도구 | 리팩토링 후 실제 UI와 지도·재계산·날짜 전환 확인 |

앞으로 사용자가 특정 스킬을 지정하거나 작업에 직접 필요한 스킬이 있다면, 해당 세션에서 제공된 `SKILL.md`를 읽고 적용한다. 사용하지 않은 스킬을 사용 이력에 추가하지 않는다. 스킬 설치 경로와 버전은 환경에 따라 바뀌므로 이 문서에 특정 캐시 경로를 고정하지 않는다.
