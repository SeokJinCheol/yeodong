# 프런트엔드 구조

아토믹 디자인은 UI 구성에 적용합니다. API 호출·비동기 상태는 `hooks`, React와 무관한 일정 규칙은 `lib/planner.ts`에서 관리합니다.

| 계층 | 책임 |
| --- | --- |
| `components/atoms` | 버튼·배지 등 기본 UI |
| `components/molecules` | 이동수단 선택, 날짜 변경 폼, 장소·길찾기 링크 |
| `components/organisms` | 구간 관리, 경로 설정, 타임라인, 지도와 요약 등 기능 단위 UI |
| `components/templates` | 공통 화면 틀 |
| `pages/PlannerPage.tsx` | 훅과 UI 연결, 날짜·선택·모달 상태 및 화면 간 동작 조율 |

## 상태와 일정 규칙

- `usePlannerData`: 초기 데이터 조회, 장소 변경, 추천 코스 배정, 변경 후 새로고침과 오류 처리.
- `useRouteSections`: 날짜별 구간 선택과 추가·이름 변경·삭제.
- `useRouteSettings`: 구간별 출발·도착지와 시간 설정. 출발·도착지·시각·시간대·이동수단·순서 모드를 서버에 저장. 날짜 이동·삭제·복사 시 서버에서 함께 처리.
- `useRoutePlan`: Valhalla 요청, 350ms 지연, 이전 요청 결과 무시, 이용 불가 상태와 강제 재계산.
- `lib/planner.ts`: 날짜 목록, 필수 STEP 배치, 저장 장소 정렬, 경로 입력 비교, 날짜별 설정 이동·삭제.

시간대·출발 시각은 변경 즉시 재계산하지 않습니다. `useRoutePlan`의 요청 의존성에 두 값을 추가하면 이 동작이 바뀝니다. 재계산 버튼은 최신 시간 설정을 사용합니다. 메모·체크리스트 수정도 경로 재계산을 유발하지 않으며, 표시 중인 장소 정보만 갱신합니다.

화면 컴포넌트에는 필요한 값과 동작 콜백을 전달합니다. API 호출이나 페이지 전체 상태를 새 UI 컴포넌트로 옮기지 않습니다.

## 일정 복사와 모바일 화면

`CopyItineraryForm`은 대상 날짜 입력을 담당하고, `usePlannerData.copyItinerary`가 복사 API 호출과 데이터 새로고침을 처리합니다. 서버가 새 장소 ID에 맞춰 출발·도착지와 시간 설정을 복제하며, `useRouteSections.selectSection`으로 대상 날짜의 복사된 구간을 선택합니다. 원본 설정은 유지합니다.

모바일에서는 `DailyItinerarySettings`의 일정 설정이 기본으로 접혀 STEP 목록을 먼저 표시합니다. 복사·날짜 이동·삭제·출발 설정은 ‘일정 설정’에서 펼칩니다. 작은 동선 탭 옆 ‘관리’ 버튼은 구간 추가·이름 변경·삭제를 펼칩니다. 데스크톱에서는 설정과 관리 버튼이 계속 표시됩니다.

## 검증

```sh
node --test tests/*.test.mjs
npm run build:nginx
```

Node.js 22.18 이상이 필요합니다. 순수 함수 테스트는 고정 STEP·왕복·다른 날짜 제외·날짜 이동·삭제 범위와 경로 재계산 입력을 검증합니다. 브라우저에서는 Map/도보 전환, 시간 변경 후 수동 재계산, 날짜 전환과 구간 폼, 지도와 STEP 링크를 확인합니다. `/yeodong/`에서 서비스할 때는 `build:nginx`를 사용합니다.

## 코드 포맷

```sh
npm run format
npm run format:check
```

`src`의 TypeScript·TSX·CSS를 정리합니다. 들여쓰기는 4칸, 중괄호 안쪽 공백은 1칸입니다. JSX 자식 태그와 여닫는 태그는 각각 줄을 나누며, 동적 표현식은 `{`와 `}` 사이에 별도 줄로 배치합니다. 짧은 단일 속성 태그는 한 줄, 여러 속성은 속성별 줄바꿈을 사용합니다.

기본 규칙은 `.prettierrc.json`, JSX 줄바꿈·공백 규칙은 `scripts/format.mjs`에서 관리합니다. JSX 텍스트의 유의미한 공백을 보존하기 위해 일부 문자열 표현식은 한 줄로 유지합니다. 포맷 과정에서 변환 전후 JavaScript 구문과 JSX 텍스트를 비교하고, 달라지면 해당 파일을 저장하지 않습니다. 일반 Prettier만 실행하면 JSX 전용 규칙이 유지되지 않으므로 위 명령을 사용하세요.

## 여행 관리와 진행 상태

- `usePlannerData`는 서버 설정 PATCH를 순차 저장하며, 삭제 후 실행 취소와 휴지통 복구를 담당합니다.
- `useTripTools`는 여행 목록·생성·이름 변경과 JSON 백업을 담당합니다. 여행 전환은 페이지를 다시 열어 이전 여행의 요청·선택 상태를 분리합니다.
- `TripTools`는 여행·백업·휴지통 UI, `ItineraryProgress`는 다음 장소·완료 현황과 순서 편집 UI입니다.
- `VisitStatusControl`은 방문 예정·방문 완료·건너뜀을 공통으로 표시합니다. 완료 항목은 접히며 상세 내용을 다시 펼칠 수 있습니다.
- 방문 상태만 바꾸어도 경로는 유지됩니다. ‘남은 장소로 재계산’을 눌러야 완료·건너뜀 장소를 제외하며 출발·도착지는 유지합니다.
- STEP 순서는 화살표 또는 드래그로 고정합니다. 자동 최적화로 돌아가려면 고정 순서를 명시적으로 해제합니다.
- 저장 장소 검색·필터는 목록에만 적용합니다. 모바일 지도/STEP 이동은 이전 스크롤 위치를 기억합니다.

## 계정 경계

`AccountGate`는 초기 세션 확인·로그인·가입을 담당합니다. 인증이 끝나기 전에는 `PlannerPage`를 마운트하지 않습니다. `useAccount` 컨텍스트는 계정 정보와 개인 기본값을 제공하고 `AccountPanel`은 저장·로그아웃 UI를 담당합니다. `api.ts`는 CSRF 토큰을 메모리에만 보관하며 여행 선택만 계정별 localStorage 키에 저장합니다. 로그인·로그아웃은 전체 새로고침으로 이전 요청을 분리하며, 다른 탭에서 계정이 바뀌면 X-Account-ID 검사로 이전 화면의 요청을 거부합니다.

## 한국어·영어 i18n

`i18next`와 `react-i18next`를 사용합니다. 로그인 화면과 설정 페이지의 언어 선택기로 즉시 전환합니다. 선택한 언어는 브라우저의 `yeodong-language`에 저장하며, 처음 방문하면 브라우저의 지원 언어(한국어·영어)를 선택하고 나머지는 한국어로 표시합니다. 계정 서버의 여행 기본값과는 별개인 브라우저 설정입니다.

- `src/lib/i18n.ts`: 초기 언어 결정, 언어 저장, 문서 언어·제목, 날짜 locale, 시스템 오류 번역.
- `src/locales/ko.json`, `en.json`: 번역 리소스. `common.button.delete`, `place.form.name`, `itinerary.copy.description`처럼 역할·기능별 의미 키를 중첩 JSON으로 관리합니다. 공통 키는 동일한 의미에만 재사용합니다.
- `LanguageSelect`: 언어 선택 UI. 새로고침이나 페이지 재마운트 없이 전환하므로 폼·날짜·구간 선택과 계산 결과를 유지합니다.
- 컴포넌트·훅의 `useTranslation()`은 언어 변경을 구독합니다. 공통 `t()`는 호출 시 현재 언어를 읽으므로 지도 이벤트와 비동기 콜백도 최신 언어를 사용합니다. 언어를 경로 요청 의존성에 추가하지 않습니다.
- 장소명·메모·여행명 등 사용자 데이터와 외부 검색 결과는 번역하지 않습니다. 알려진 서버 오류는 표시 시 번역하고 알 수 없는 메시지는 원문을 보존합니다.
- 호출 예: `t('common.button.delete')`, `t('place.count', { count: 2 })`, `t('account.greeting', { name })`. 키에는 문구·공백·중괄호를 넣지 않습니다. 공백·조사·기호·어순과 `{{name}}` 같은 보간 표기는 번역 값 안에서 처리합니다. 숫자 문구는 `_one`/`_other`로 단복수를 처리합니다.
- `t()`의 키는 한국어 리소스에서 추론한 `TranslationKey`로 제한하여 오타·누락을 타입 검사합니다. 서버의 기존 문자열 오류는 `translateMessage()`에서 시스템 메시지 키로만 연결하고, 모르는 원문은 보존합니다.
- 번역 추가 시 두 JSON의 키와 이름 있는 보간 변수(`name`, `count`, `time` 등)를 맞춥니다. `node --test tests/*.test.mjs`는 번역 일치, 언어 우선순위, 저장소 차단, 문서 언어 변경과 기존 일정 규칙을 검증합니다.


## 프로필 메뉴와 설정 페이지

- 헤더의 프로필 버튼을 누르면 설정과 로그아웃이 표시됩니다. Escape·바깥 클릭·포커스 이동으로 닫히며 키보드로도 사용할 수 있습니다.
- `pages/WorkspacePage.tsx`가 인증 뒤 공통 레이아웃과 `usePlannerData`를 한 번만 구성합니다. `usePageNavigation`은 `#/`와 `#/settings`, 브라우저 뒤로·앞으로 이동을 처리합니다. 해시 경로이므로 `/yeodong/` nginx 설정을 추가하지 않아도 됩니다.
- `SettingsPage`는 언어, 개인 기본값, 여행 전환·관리, 백업·휴지통을 담당합니다. 여행 화면에는 해당 패널과 별도 로그아웃 버튼이 없습니다.
- 설정을 방문할 때 여행 화면을 숨겨 날짜·구간·계산 결과·작성 중 폼을 유지합니다. 숨겨진 폼은 스크롤 잠금을 해제합니다. 처음부터 설정 주소를 열면 여행 화면은 방문할 때까지 마운트하지 않습니다.
- 기본값 저장은 기존 계정 API, 여행·백업은 `useTripTools`, 가져오기·복구는 공유 `usePlannerData`의 변경 흐름을 사용합니다. 설정에서 바꾼 데이터가 여행 화면에도 반영되며, 계정 전환과 여행 전환의 전체 새로고침 규칙을 유지합니다.
